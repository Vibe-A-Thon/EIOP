======================================================================
NON-NEGOTIABLE CONSTRAINTS
======================================================================

1. NO CLOUD SERVICES.

2. The entire platform must be capable of running on-premises / local infrastructure.

3. Use Docker containers.

4. Use Docker Compose for the MVP.

5. Apache HugeGraph must be the primary graph database and the authoritative graph/ontology store.

6. Do not introduce Neo4j, Neptune, Cosmos DB, Amazon services, Azure services, GCP services or SaaS dependencies as required infrastructure.

7. Additional local/self-hosted components may be proposed ONLY when they solve a clearly identified problem that HugeGraph should not solve.

8. Every additional infrastructure component must be justified.

9. Minimize infrastructure complexity in the MVP.

10. Do not implement RBAC for the MVP.

11. Different applications/views may use separate URL patterns and screen-switch modes.

12. Explicitly state that URL separation is NOT a security authorization boundary.

13. MVP deployment may assume:
    - trusted enterprise network,
    - development environment,
    - single-user environment,
    - or controlled demonstration environment.

14. Even without RBAC, implement:
    - authentication where appropriate,
    - secret protection,
    - network isolation,
    - TLS where appropriate,
    - audit logs,
    - agent/tool action controls,
    - destructive-action confirmation,
    - secure configuration,
    - data sanitization.

15. NO enterprise production data may leave the local environment.

16. AI inference should be LOCAL-FIRST.

17. Support local/self-hosted models through a model abstraction layer.

18. External LLM endpoints must be disabled in the MVP.

19. The architecture MAY include an optional provider abstraction for future use, but:
    - it must be disabled by default,
    - no real enterprise data can be transmitted,
    - only approved synthetic/redacted information may ever be sent if such functionality is later enabled.

20. Prefer deterministic algorithms, graph algorithms, parsers, rules and conventional software engineering whenever an LLM is unnecessary.

21. Use LLMs only where they materially improve functionality.

22. The system must remain useful even when no LLM is available.

23. Clean-room implementation is mandatory.

24. Study capabilities and ideas from existing products, open-source projects, research papers and industry systems, but:
    - do not copy proprietary source code,
    - do not plagiarize implementations,
    - respect licenses,
    - document inspirations,
    - build an independently engineered implementation.

25. Generate SBOM/dependency/license documentation.

26. The architecture must support offline or highly restricted-network deployment.
