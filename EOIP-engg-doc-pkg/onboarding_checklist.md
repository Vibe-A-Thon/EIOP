# EOIP Onboarding Checklist

Reusable checklist; session-specific status belongs in [context](context.md),
[memory](memory.md) and [checklist](checklist.md).

- [ ] Read the full coordination packet and existing tickets listed in
  [instruction](instruction.md); preserve its two KGR scope exclusions.
- [ ] Inspect actual branch, HEAD, dirty files and applicable specs/code.
- [ ] Select the assigned charter in [roles](roles.md); copy its exact active persona.
- [ ] Reconcile placeholders/stale claims with evidence; label unknown values.
  Do not overwrite verified history or invent tests, PRs, owners or dates.
- [ ] Verify paths/commands using [agent runbook](agent_runbook.md); check prerequisites
  before execution. Do not use generic sample scripts.
- [ ] Select a real dependency-ready ticket from [todo-status](todo-status.md).
  Create only justified gaps/proposals with the [ticket template](tickets/ticket-template.md).
- [ ] Record session start, scope, owner/verifier and approval boundaries.
- [ ] Keep ticket status, queue, [requirements map](tickets/requirements-map.md)
  and acceptance checklist synchronized.
- [ ] Run scoped verification; record exit codes, receipts and unexecuted checks.
- [ ] Update context and append the [handoff](handoff_template.md) to memory;
  context links to the latest memory block instead of duplicating its history.
- [ ] Validate local links, ticket rollups, active persona and status consistency.
- [ ] Commit/push/deploy only if explicitly approved; otherwise record
  working-tree persistence and **not requested** publication status.

For later sessions use [continue from left over](onboarding_prompts.md), not
automatic re-onboarding or compulsory creation of three tickets.
