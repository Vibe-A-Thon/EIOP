## 3. Self-inversion cards (EOIP's own verified weaknesses, Master Prompt §10.4 "apply the same engine to our own platform's weaknesses")

Every P0 gap in `07-GAP-REGISTER.md` gets a card here, in the same format as a competitor inversion card: target (EOIP itself, version/commit); evidence-supported limitation; root cause (proven/hypothesis); why an alternative design mitigates it and when it would be worse; three options; selected option with trade-offs; falsifiable benchmark; dependencies and failure cases; defensibility; decision.

### INV-SELF-01 — Source-ACL enforcement not applied on deployed paths (GAP-02)
- **Target:** EOIP @ HEAD 896e06d, `retrieval/service.py`, `authz/pdp.py`, MCP surface, exporters.
- **Limitation (proven):** the derivation-ACL filter exists but is called in only one branch of `retrieve()`, gated on a `scope` argument that no deployed caller passes (01a-BASELINE-DELTA-HEAD.md BL-18). Keyword, vector and hybrid candidate stages filter by tenant only, not by source ACL. The Obsidian exporter (`exporters/obsidian_vault.py`) and the MCP tool surface inherit the same gap.
- **Root cause:** coupling — ACL enforcement was built as an opt-in library call rather than a mandatory stage of the retrieval and export pipelines.
- **Alternative and when it would be worse:** making ACL-filtering mandatory and unconditional is strictly better for correctness; it would only be "worse" if it measurably hurt latency at scale, which BM-04 must check before rollout.
- **Three options:** (1) quick integration — make the existing filter mandatory (non-optional parameter) in `retrieve()` only; (2) pragmatic native enhancement — propagate ACL principals through every candidate-generation stage (keyword, vector, hybrid) plus a delivery-time re-check; (3) long-term differentiated architecture — ACL-embedded indexes (per STR-onyx-01, STR-opensearch-01) with Zanzibar-style consistency tokens on revocation (STR-rebac-01).
- **Selected option:** (2) now, (3) as the target architecture. Every fact, chunk and edge carries an ACL-principal set at write time; every retrieval stage pre-filters candidates by the caller's resolved principal set; a final check runs at delivery; a consistency token is checked on any permission change.
- **Falsifiable benchmark:** BM-04 — two synthetic users with disjoint permissions ask the same question; zero leaked facts in the answer, citations, cache or memory is the pass condition; dataset and harness in `15-VALIDATION-BENCHMARK-PLAN.md`.
- **Dependencies/failure modes:** CAP-47 (tenant isolation) must land first or ACL and tenant scoping collide; failure mode is a stale principal set after a permission revocation (mitigated by the consistency token).
- **Defensibility:** this is table-stakes correctness, not a moat by itself — but *measured, benchmarked* zero-leakage under revocation is defensible because most competitors (per the cohort files) do not test or document this at all.
- **Decision:** ADOPT.

### INV-SELF-02 — Tenant isolation not enforced in graph adapters (GAP-03)
- **Target:** `graph/hugegraph.py`, `graph/neo4j.py`, `graph/neptune.py`, `graph/memory.py` @ HEAD — zero tenant references (01a BL-20).
- **Limitation (proven):** `tenancy/isolation.py` defines a placement *contract* (SILO/BRIDGE/POOL) but physical enforcement is explicitly an "External gate"; no adapter code reads a tenant context.
- **Root cause:** deployment/storage — tenancy was designed as an operational convention (separate deployments) rather than a data-plane guarantee.
- **Alternative and when it would be worse:** a data-plane guarantee is strictly better for a shared-pool deployment model; for SILO (dedicated stack per tenant) the operational convention is sufficient and a data-plane check is redundant overhead — so the fix should be conditional on isolation model, not universal.
- **Three options:** (1) quick integration — add a tenant-id property + predicate on every query path for POOL/BRIDGE models; (2) pragmatic native enhancement — per-backend native isolation unit (HugeGraph graph space, Neo4j multi-db, Neptune cluster-per-tenant) chosen by `IsolationPlacement`; (3) long-term — a tenant-aware `GraphStore` protocol that refuses any call without a resolved tenant context, backend-neutral.
- **Selected option:** (2) immediately for new deployments, (3) as the protocol-level target.
- **Benchmark:** BM-05 — two tenants, adversarial cross-tenant query attempts, zero leakage across data, index, cache, log and memory.
- **Dependencies/failure modes:** interacts with GAP-02; failure mode is a backend whose native isolation unit the adapter does not yet use (tracked per-backend in `02-TECHNOLOGY-REGISTRY.md`).
- **Defensibility:** backend-neutral tenant isolation, proven by the same benchmark across HugeGraph/Neo4j/Neptune, is not offered by any single-backend competitor researched.
- **Decision:** ADOPT.

### INV-SELF-03 — Egress vault uses an unauthenticated XOR keystream cipher (GAP-08)
- **Target:** `egress/vault.py` @ HEAD.
- **Limitation (proven):** the reversible tokenisation vault encrypts with XOR keystream, which has no integrity check and is trivially broken if the keystream repeats or is partially known.
- **Root cause:** algorithm — a placeholder cipher was never replaced with an authenticated one.
- **Alternative:** an AEAD cipher (AES-GCM or ChaCha20-Poly1305) is strictly better with negligible added latency; there is no case where XOR is preferable.
- **Three options:** (1) quick integration — swap to AES-GCM from the stdlib/`cryptography` package; (2) pragmatic native enhancement — add key rotation and envelope encryption; (3) long-term — optional OpenBao (MPL-2.0) Transit integration for customers who want a managed KMS, keeping the native AEAD path as the default (Vault itself is BUSL and excluded from bundling).
- **Selected option:** (1) now, (3) as an optional integration.
- **Benchmark:** BM-18 — cryptographic review checklist + a known-plaintext-recovery test that must fail against the new cipher.
- **Dependencies/failure modes:** key-management story must exist before rollout (where keys are stored, rotated).
- **Defensibility:** not a differentiator — a correctness bar every competitor should already clear; EOIP closing it removes a real liability.
- **Decision:** ADOPT.

### INV-SELF-04 — MCP surface authenticates one shared bearer token (GAP-09)
- **Target:** `apps/mcp/main.py:220-223` @ HEAD; `EOIPMCPServer` / `tools_contract/mcp_server.py` not mounted (01a BL-47).
- **Limitation (proven):** every MCP caller is the same principal; no per-user authorization; tools carry no read-only/write annotations.
- **Root cause:** coupling — the MCP transport was built before a per-caller identity model existed.
- **Alternative:** an OAuth 2.1 resource-server model (per the MCP spec's own authorization extension) lets each agent/user carry its own token, closing both the confused-deputy risk (C09-mcp INV-mcp-01) and the ACL gap (GAP-02) for the MCP surface specifically.
- **Three options:** (1) quick integration — per-deployment tokens instead of one global token; (2) pragmatic native enhancement — OAuth 2.1 resource server with per-user scopes mapped to the existing RBAC/ABAC model; (3) long-term — signed, hash-pinned tool manifests (C09-mcp INV-mcp-01) plus tool annotations (read-only hints) enforced server-side.
- **Selected option:** (2) now, (3) alongside.
- **Benchmark:** BM-18 — a malicious tool-poisoning and confused-deputy test suite; pass requires every tool call to be attributable to a real end-user principal and ACL-checked.
- **Dependencies/failure modes:** depends on GAP-02's ACL propagation; failure mode is a legacy integration that only supports the shared-token model.
- **Defensibility:** per-user MCP authorization combined with ACL-aware tools is not demonstrated by any researched competitor's MCP server.
- **Decision:** ADOPT.

### INV-SELF-05 — Backend adapters unproven live; known adapter defects (GAP-01)
- **Target:** `graph/janusgraph.py`, `graph/neptune.py`, `graph/hugegraph.py` @ HEAD.
- **Limitation (proven by code reading, not yet by a live run):** JanusGraph adapter writes `p_`-prefixed property keys but reads unprefixed ones (likely breaking non-canonical-id lookups); Neptune adapter has no SigV4 signing and filters edge labels after applying `LIMIT` (silent truncation); HugeGraph forces a Groovy closure that will not run on gremlin-lang-only backends (TinkerPop 4.0 direction).
- **Root cause:** algorithmic/implementation defects, proven by static reading; severity unconfirmed live (U-01).
- **Alternative:** fix each defect and add a conformance suite that runs the same workload against every backend, so regressions are caught before release.
- **Three options:** (1) quick integration — patch the three named defects; (2) pragmatic native enhancement — a shared conformance test suite (BM-01) run in CI against live containers of each backend; (3) long-term — the typed query-IR compiler (GAP-04) removes an entire class of per-backend string-building defects by construction.
- **Selected option:** (1) immediately, (2) as a standing CI gate, (3) as the structural fix.
- **Benchmark:** BM-01 — identical read/write/traversal workload run against HugeGraph, Neo4j, Neptune and JanusGraph containers; results must match within documented semantic differences.
- **Dependencies/failure modes:** requires live container access in CI (not available in this research run — see BASELINE_UNCERTAINTIES U-01).
- **Defensibility:** a passing cross-backend conformance suite, published per release, is stronger and more verifiable than any single competitor's single-backend guarantee.
- **Decision:** ADOPT.

### INV-SELF-06 — Epistemic planes not enforced store-wide (GAP-07)
- **Target:** `ai/boundary.py` contract vs. per-backend storage @ HEAD.
- **Limitation (proven):** PROPOSED-until-promoted is enforced in the boundary module's own logic but is not a storage-level plane (label/namespace) on every backend; a write that bypasses the boundary module could still land as an "observed" fact.
- **Root cause:** governance/coupling — the guarantee lives in application code, not in the storage schema.
- **Alternative:** encode the epistemic state as a required, backend-native label/property that the mutation gateway refuses to omit, so bypassing the contract requires bypassing the gateway entirely (already a validated failure mode worth closing separately).
- **Three options:** (1) quick integration — add a required `epistemic_state` property enforced by `validation/gate.py`; (2) pragmatic native enhancement — per-backend namespace/label separation (e.g. distinct vertex labels or a graph partition) for PROPOSED vs CORROBORATED facts; (3) long-term — a promotion workflow with audit trail and reviewer sign-off, feeding `provenance/warrant_composition.py`.
- **Selected option:** (1) immediately, (2) and (3) as the target.
- **Benchmark:** BM-15 — attempt to write an "approved" fact through every ingestion path without going through promotion; all attempts must fail.
- **Dependencies/failure modes:** interacts with GAP-34 (agent memory) which has the same class of problem for memory records.
- **Defensibility:** verifiable separation of observed/inferred/predicted/approved, backed by a storage-level guarantee rather than an application convention, is a differentiator per the capability matrix (CAP-43: no researched competitor provides this natively).
- **Decision:** ADOPT.

### INV-SELF-07 — No unified evaluation harness with regression gates (GAP-43)
- **Target:** `qa_bench/`, retrieval eval (`retrieval/eval.py`) @ HEAD — deterministic only, no cross-cutting harness.
- **Limitation (proven):** every claim in this research package about EOIP's own behaviour at scale, under adversarial input, or across backends is currently unverifiable because no harness runs BM-01 through BM-22 together with regression thresholds.
- **Root cause:** operational — benchmark infrastructure was never built as a first-class deliverable.
- **Alternative:** build the harness once, as the single place every BM-ID in `15-VALIDATION-BENCHMARK-PLAN.md` executes, with pass/fail thresholds checked in CI.
- **Three options:** (1) quick integration — wire existing ad hoc tests into one `pytest` marker set with thresholds; (2) pragmatic native enhancement — a dedicated harness project (`qa_bench` extended) with fixtures, generators and reproducibility metadata (hardware, dataset, versions); (3) long-term — a public benchmark dashboard comparable to LDBC-style audited runs (labelled "not LDBC Benchmark Results" per LDBC's trademark terms).
- **Selected option:** (2) now, (3) as a later credibility move.
- **Benchmark:** the harness is itself the deliverable; its own test is "does every BM-ID in §15 execute and gate a release".
- **Dependencies/failure modes:** every other self-inversion card's benchmark depends on this harness existing.
- **Defensibility:** reproducible, gated evidence is the precondition for every other claim in this package to be trustworthy — it is infrastructure, not a feature, but its absence undermines every other claim.

### INV-SELF-08 — String-built Gremlin and regex-only injection defences (GAP-05)
- **Target:** `adapters/janusgraph.py:192,276`, `graph/hugegraph.py:525-551`, `agents/firewall.py` @ HEAD.
- **Limitation (proven):** property keys and labels are spliced into Gremlin/Groovy scripts as strings in two adapters; the agent firewall relies on regex patterns only.
- **Root cause:** implementation — queries were built before a parameterised query path existed for these backends.
- **Alternative:** parameterised gremlin-lang (TinkerPop 4.0 direction, STR-tinkerpop-01) removes the injection surface by construction; a classifier layer supplements (not replaces) the regex firewall for untrusted text.
- **Three options:** (1) quick integration — parameterise the two named call sites; (2) pragmatic native enhancement — route every backend call through the QueryPlan compiler so no hand-built script ever reaches a backend; (3) long-term — adopt gremlin-lang + typed parameters as the only wire format once TinkerPop 4.0 is stable (currently beta, per C12-tinkerpop).
- **Selected option:** (1) immediately, (2) as the structural fix, (3) tracked for later.
- **Benchmark:** BM-18 — an injection corpus (malicious property keys/labels) run against every adapter; zero successful injections is the pass condition.
- **Dependencies/failure modes:** (2) depends on GAP-04 (query-IR compiler); TinkerPop 4.0 is still beta, so (3) is not yet actionable.
- **Defensibility:** this closes a real vulnerability; it is not a market differentiator by itself.
- **Decision:** ADOPT.

### INV-SELF-09 — Agent memory lacks ACL, tenant, evidence and validity fields (GAP-34)
- **Target:** `memory_eng/engine.py`, `reasoning/memory.py`, `agents/memory.py` @ HEAD.
- **Limitation (proven):** memory records carry no ACL principal set, tenant scope, evidence pointer or validity window — the same structural gap as every competitor researched (C08-cognee, C08-mem0, C08-graphiti-zep, C08-letta all show the same absence).
- **Root cause:** coupling — memory was built as a cache of conversation state, not as a governed knowledge type.
- **Alternative:** treat memory records as first-class epistemic objects (see GAP-07) with the same ACL/tenant model as graph facts (GAP-02/GAP-03), re-checked on every read.
- **Three options:** (1) quick integration — add ACL/tenant/evidence/validity fields to the existing memory schema; (2) pragmatic native enhancement — memory writes go through the same mutation gateway and promotion workflow as graph facts (propose-not-write, per Letta's "dreaming" subagent risk in C08-letta INV-letta-01); (3) long-term — memory becomes a queryable view over the governed graph rather than a separate store.
- **Selected option:** (1) immediately, (2) as the target, (3) as a research direction.
- **Benchmark:** BM-04/BM-05 extended to memory — a revoked user's prior memory must become inaccessible immediately (consistency-token check, per GAP-02).
- **Dependencies/failure modes:** depends on GAP-02 and GAP-07 landing first.
- **Defensibility:** no researched agent-memory competitor enforces ACL/tenant/evidence on memory; doing so correctly, with a passing benchmark, is a genuine and currently unclaimed differentiator.
- **Decision:** ADOPT.

### INV-SELF-10 — Local model runtime pinned to an old, root, unauthenticated Ollama (GAP-36)

### INV-SELF-11 — No licence allow-list in CI; several attractive components block OEM (GAP-19)
- **Target:** EOIP's dependency and research-recommendation pipeline as a whole; no CI gate found.
- **Limitation (proven):** the research package itself documents numerous AGPL/SSPL/BSL/ELv2/commercial-only components that would block a white-label OEM product if adopted without review (Zingg AGPL-3.0, FalkorDB SSPL, Vault BUSL, Grafana AGPL-3.0, Elasticsearch AGPL/SSPL/ELv2, Airbyte mixed ELv2/MIT, Redpanda BUSL, TruffleHog AGPL-3.0, PM4Py AGPL-3.0, igraph GPL-2.0, Raphtory GPL-3.0, Logseq AGPL-3.0, several OWL reasoners LGPL/AGPL) — and no automated check exists to catch a future dependency addition that would silently reintroduce one of these.
- **Root cause:** operational/governance — licence review has been manual and ad hoc (per-feature decisions scattered across the registry) rather than enforced in CI.
- **Alternative:** a CI step that fails the build when a new dependency's declared licence is not on an explicit allow-list, with a documented exception/legal-review queue for anything else.
- **Three options:** (1) quick integration — a licence-checker CI step (e.g. scanning `requirements.lock` and `package-lock.json`) against an allow-list derived from `02-TECHNOLOGY-REGISTRY.md` §3; (2) pragmatic native enhancement — extend the allow-list check to container images and bundled binaries, not just language-package manifests; (3) long-term — an automated SBOM (GAP-44) cross-checked against the allow-list on every release.
- **Selected option:** (1) immediately, (2) and (3) as the target (they share infrastructure with GAP-44).
- **Benchmark:** BM-20 — introduce a dependency with a known-blocked licence in a test branch; the CI gate must fail the build.
- **Dependencies/failure modes:** shares infrastructure with GAP-44 (SBOM/signing); legal review still has final say on any exception.
- **Defensibility:** not a market differentiator; it is risk management that protects the OEM/white-label business model (CAP-52) that *is* a differentiator.
- **Decision:** ADOPT, P0 (forced — licensing gate, Master Prompt §17).
