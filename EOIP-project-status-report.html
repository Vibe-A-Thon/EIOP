Product and scope

What EOIP is meant to be, what exists today, and how far the suite of applications has progressed.

Vision

A self-hosted living organizational brain. It connects to every work system, builds knowledge, code and meta graphs into one continuously updated brain, and lets anyone in any role ask any question and get an answer with evidence, confidence and related answers.

First job

  • What implements this requirement?
  • What changes if this code changes?
  • Why do we believe this link exists?

All three work today through the WHY / IMPACT / PATH / WHAT CHANGED operators.

Non-negotiables

  • Local-first; cloud only if the client chooses
  • Core works offline, with the model stopped, and without a vector database
  • History is never destroyed
  • Every link carries its evidence
  • No GPL/AGPL dependencies

Strengths and structural concerns

  • Ports and adapters: GraphStore and SourceConnector interfaces
  • Bitemporal revision model: "what was true at V" and "what did we know at S"
  • Governed query plans: natural language never becomes executable Gremlin
  • Ontology GitOps and 14 graph domains
  • Egress gateway with data-flow manifests and DLP
  • API composition in three oversized files (1,703 · 1,982 · 1,579 lines) plus a 2,051-line platform router
  • Graph-of-graphs projections are built in memory and thrown away
  • Single-node file queue; no distributed job execution
  • Several "router" packages for overlapping concerns
  • No import boundary between the core and the experimental code

  1. Day-0 model: pinned local LLM and embedding model per hardware tier (WP-G01)

Security and privacy

Strong platform security, with one critical gap that blocks opening the product to the whole organization.

Critical gap: answers are not permission-aware. Source-system access rules (Jira project roles, Confluence page restrictions, repository membership) are never captured or enforced. A viewer could receive facts from items they cannot open in the source. Fix: WP-A02.
