17 RAG Patterns

Queries are classified and routed to the optimal retrieval pattern

Core Patterns

  • Simple — keyword match, 1-hop BFS
  • Advanced — query expansion + reranking
  • Graph — community summarize + merge
  • Hybrid — vector + graph + BM25
  • HyDE — hypothetical doc embedding

Adaptive Patterns

  • Corrective — retrieve, evaluate, correct
  • Self — retrieve, generate, self-evaluate
  • Adaptive — classify, route, adapt
  • Agentic — agent plan, retrieve, reflect
  • Modular — compose, retrieve, fuse

Advanced Patterns

  • Conversational — context carry + coreference
  • Multi-step — decompose, chain
  • Multi-hop — hop, retrieve, hop
  • Branched — parallel retrieve, compare
  • Multimodal — cross-type alignment
  • Speculative — speculate, validate, prune
  • RAG of RAGs — meta-orchestrate + fuse
All 17 patterns use the graph as their primary context source. No vector database required — the graph IS the retrieval engine.

Architecture

Layered architecture with graph authority and evidence-first design

13 connectors → SourceEvent contract → Mapper → Validator → Graph Mutator → HugeGraph

Intelligence Layer

RAG Router (17 patterns) · Agent Router (41 types) · LAYA Engine (8 capabilities) · Engineering Disciplines (8)

12 query types · EQL parser · NL intent classifier · Graph traversal (BFS/DFS) · Impact analysis

API Layer

FastAPI with 40+ endpoints · MCP Server (17 tools) · VS Code Extension · Prometheus metrics

Pipeline Stages

FETCH — acquire from source ↓ MAP — transform to schema ↓ VALIDATE — check constraints ↓ MUTATE — write to HugeGraph ↓ VERIFY — confirm graph state ↓ LINK — cross-domain edges ↓ SNAPSHOT — backup + audit

Honest Boundaries

What we demo is what we deliver — no hidden dependencies or aspirational claims

What Works Today

  • Graph and analytics are live behavior over persisted data
  • All golden paths work without a local LLM
  • 13 connectors with validated JSON formats
  • 17 RAG patterns with intent-based routing
  • 41 agent types with graph-grounded execution
  • 8 LAYA capabilities with deterministic fallback
  • 12 query types including NL and EQL
  • Full backup/restore with checksum verification

Noted Limitations

  • Source exports are offline fixtures unless credentials configured
  • Model synthesis is optional (LAYA uses fallback without LLM)
  • Container hardening is not yet production-grade
  • Performance benchmarks are not demo claims
  • G2 roadmap items are future work, not current capability
  • Crawler operates on mock data in demo mode
