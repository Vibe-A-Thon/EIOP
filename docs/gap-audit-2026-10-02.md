### Gap 22: schema compatibility

`HugeGraphStore.ensure_schema` now fetches property keys, vertex labels, edge
labels and index labels before issuing a POST, PUT or DELETE. It checks types,
cardinality, IDs/primary keys, endpoints/frequency/sort keys, label indexes,
nullability, required-property additions and same-name index definitions.
Missing compatibility metadata fails closed. Errors identify the object and
field and direct operators to an explicit backed-up migration or empty graph.
Automatic incompatible index replacement is intentionally removed; compatible
nullable additions and known obsolete-index cleanup remain supported.

This closes the specified incompatible-bootstrap refusal behavior, not a
general schema-version migration/catalog or a guarantee against concurrent
external schema writers. See [local Docker guidance](docker-local.md).

### Gap 19: canonical ingestion boundary

`ingestion/pipeline.py` now consumes `GraphMutation` rather than constructing and
discarding it. All eight service implementations route writes through the adapter:
Jira JSON, GitLab JSON, local code, local repository, GitHub REST, GitLab REST,
Jira REST and generic source sync (including Confluence/ServiceNow and registry
adapters). Temporal evolution and domain linking use the same boundary.

The consumer revalidates normalized models against the local contract shapes,
requires nonblank mutation/run IDs, rejects identity/domain contradictions and
invalid confidence/status values before the affected write, and retains existing
hard ontology gates. Physical endpoints become canonical envelope IDs without
changing fact-based edge identity or persisted graph projections. Revision
properties keep their existing subject-type semantics. Run context is isolated
per execution context. Repository metadata is durably captured before its first
graph vertex, and guarded service tests enforce capture-before-write ordering.

Scope and failure behavior:
- Envelopes are transient, in-process boundaries, not a new durable mutation queue.
- Available source/evidence references are retained without fabricating provenance
  for infrastructure vertices. Raw captures remain authoritative.
- Contract errors propagate explicitly; they do not automatically create a new
  canonical-validation DLQ entry. Earlier writes in the same run are not rolled
  back, but the invalid proposal is not written and captured input is preserved.
- Missing-entity deletion retains its `false` no-op result; existing tombstones
  pass through the consumer. Temporal edge expiry remains an upsert, not an
  unsupported edge tombstone.
- Administrative schema/reset/snapshot bulk operations and demo meta bootstrap
  are not source-ingestion boundaries and retain their existing store semantics.
- This closes gap 19's wiring requirement, not live-source, full-scale performance,
  native recovery or complete application certification.
