## Implementation progress — 2026-10-03

The following audited gaps are now implemented and covered by automated tests:

- **P0-4 hard validation gates:** both graph stores reject unknown labels/properties and invalid relationship endpoints before mutation; ingestion failures use the unified DLQ envelope.
- **P1-8 tombstone semantics:** authenticated idempotent delete endpoint, deleted-by-default entity/search reads, explicit `include_deleted`, active-edge conflict findings, and source reappearance recovery.
- **P1-9 deterministic replay:** preserved captured-event identity/timestamps, durable `REPLAY` worker jobs, operator CLI, stable logical graph projection, and golden-output drift comparison.
- **P1-10 DLQ unification and replay:** one safe envelope across ingestion services; Jira, GitLab, and local-code replay; registered SourceEvent v2 replay routing for GitHub, Confluence, ServiceNow, and other registry-backed sources.
- **P1-14 MCP completeness:** bounded `neighbors` and `document` tools plus structured tool-error envelopes.
- **P1-15 audit fail-closed:** mutating admin requests require a durable audit preflight; HTTP 422 refusals are policy denials; worker, backup, and restore events use the persistent audit sink.

Verification: `python -m ruff check .` and the full `python -m pytest -q` suite passed on 2026-10-03.

## P0 — blocks MVP acceptance (fix first)

1. **HugeGraph edge dedup** (FR-INGEST-003). `packages/eoip/graph/hugegraph.py` `upsert_edge` always POSTs a new edge; re-ingest duplicates every edge on the real backend. Add UNIQUE `edge_key` index in `ontology/manifest.py` and GET-then-create (or query-by-key) semantics; prove with a HugeGraph-backed double-ingest test (not MemoryGraphStore).
2. **NL → QueryPlan interpretation** (FR-QUERY-005, MVP-FR-013/016). No natural-language path exists. New `packages/eoip/query/nl.py`: rule/regex fast path (issue key, commit SHA, symbol name, "what implements/impacts X" → SEARCH/PATH/IMPACT/TRACEABILITY), optional local-model plan drafting validated against the QueryPlan schema, deterministic fallback + structured refinement response; `POST /api/v1/query/nl`; adversarial fixtures in `tests/security/`.
3. **Identity resolution wired into ingestion** (FR-ID-001). Jira and Git create *different* Person URNs for the same email (`ingestion/jira.py:184` vs `ingestion/repository.py:82`). Route both through `IdentityResolver` with one canonical namespace keyed by casefolded email; retain source aliases on Person; add cross-source merge test.
4. **Hard validation gates in the mutation path** (FR-VALID-002). Endpoint/domain-range + required-property checks only run post-ingestion. Add a shared `validation/gate.py` invoked before every `upsert_edge`/`upsert_vertex` in all four ingestion services; quarantine invalid facts; keep soft rules in `ValidationEngine`.
5. **Quality N/A rule + missing metrics** (FR-VALID-003). `validation/quality.py` returns 1.0 for empty denominators (must be "N/A"); add orphan rate, duplicate rate, freshness, completeness, schema-compliance metrics; fixture-reconciliation test.
6. **RAG evaluation harness** (FR-RAG-005). New `packages/eoip/retrieval/eval.py` (EvalCase/EvalResult: precision/recall, evidence coverage, groundedness, latency) + golden QA fixture over the demo corpus + `scripts/rag_eval.py` producing a reproducible baseline report.

## G2 roadmap (phase-by-phase, after P0/P1)

- **G2-P0:** SourceEvent v2 envelope (operation, event_time, cursor, permissions) + v1 adapter; canonical revision model (valid_from/valid_to/is_current/previous_revision) + ADR; source registry schema.
- **G2-P1 (EKAF):** source registry persistence, scheduler (baseline/poll/reconcile/replay), webhook gateway, controlled web crawler (allowlists, SSRF guards, dedup), DLQ/replay console, discovery/dry-run.
